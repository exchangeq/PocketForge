# game-dev.md · 游戏项目规范

## 1. 适用场景

像素风小游戏、文字冒险、点击放置、卡牌、横版跑酷、解谜、Roguelike 原型。
用户说「做个游戏 / 小游戏 / 能玩的 demo / 游戏原型」时启用。

## 2. 技术选型（按优先级）

| 优先级 | 方案 | 适用 | 说明 |
| --- | --- | --- | --- |
| 1 | **单文件 HTML5 + Canvas** | 任何 2D 小游戏 | 双击即玩，无构建，最容易验收 |
| 2 | **HTML5 + 多文件**（`index.html` + `js/`） | 需要拆模块时 | 用 ES Module，`file://` 也能跑则不拆 |
| 3 | **Godot 4 工程文件**（`project.godot` + `.tscn` + `.gd`） | 用户明确要 Godot | 只产出可导入的工程结构，不在手机上构建 |
| 4 | **纯 Kotlin / Java 逻辑层** | 用户指定 Android 原生 | 只输出逻辑与接口，标注「需在 PC 编译」 |

**不允许**：声称在手机上编译 APK、引入需要 `npm install` 才能跑的框架、引用 CDN 上不确定存在的库。
确需第三方库时，优先 `<canvas>` 手写；必须用库则锁定版本并写进 `README.md` 的「依赖」一节。

## 3. 目录结构（强制）

```
projects/<项目>/
├── README.md            # 一句话玩法 + 操作 + 运行方式
├── PROJECT.md           # 项目卡（由 project_new 生成）
├── AGENTS.md            # 给 AI 的开工须知
├── plan/todo.md         # 分步任务
├── design/
│   ├── gdd.md           # 核心循环 / 操作 / 关卡 / 数值
│   └── tech.md          # 技术方案 / 存档格式
├── src/
│   ├── index.html       # HTML5 主入口
│   ├── game.js          # 主循环
│   ├── entities.js      # 玩家/敌人/道具
│   └── style.css
├── assets/
│   ├── images/          # 用色块/几何图形代替位图，文件名说明用途
│   ├── audio/           # 留清单即可，不放二进制
│   └── data/            # 关卡 JSON、数值表
└── build/               # 构建产物（HTML5 直接放打包后的 zip）
```

## 4. 分阶段交付

| 阶段 | 产出 | 验收 |
| --- | --- | --- |
| P0 立项 | `design/gdd.md` 核心循环一段话 | 用户能在 30 秒内看懂「怎么玩」 |
| P1 可动 | 玩家可移动/攻击，一个敌人 | 打开 `index.html` 能操作 |
| P2 有循环 | 分数/血量/失败/重开 | 输一次能重开 |
| P3 有内容 | 3 关或 3 种敌人、难度曲线 | 数值表写进 `assets/data/` |
| P4 打磨 | 音效占位、动效、README 完整 | 新用户不用问就能玩 |

一次只推进一个阶段；没验收通过不写下一阶段。

## 5. 代码约定

- 单文件优先，函数不超过 80 行；主循环固定 `requestAnimationFrame` + `deltaTime`。
- 所有可调数值集中在文件顶部 `CONFIG` 对象，禁止散落魔法数字。
- 输入统一走一个 `Input` 模块，支持键盘 + 触屏（移动端必须能玩）。
- 存档用 `localStorage`，键名 `pf.<项目名>.save`，结构必须能向后兼容（带 `version` 字段）。
- 中文注释只写「为什么」，不写「这行是干嘛」。

## 6. 素材与版权

- 不生成/不引用有版权的角色、音乐、字体（可用系统字体、几何图形、程序化音效）。
- 位图用 SVG 或 Canvas 绘制的色块；音频用 Web Audio 合成占位。
- `assets/images/` 里每个文件配一行说明（用途 + 尺寸 + 授权来源）。

## 7. 自检清单

- [ ] `index.html` 用手机浏览器能直接打开并操作
- [ ] 触屏可玩（不只键盘）
- [ ] 数值集中在 CONFIG，改一处即调平衡
- [ ] 无外部未锁定依赖
- [ ] README 写明：玩法 / 操作 / 运行 / 已知限制
