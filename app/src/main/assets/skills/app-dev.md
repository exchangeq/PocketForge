# app-dev.md · 应用 / 网页项目规范

## 1. 适用场景

单页工具、计算器、清单、看板、表单、落地页、小游戏之外的交互原型。
用户说「做个网页 / 小工具 / App 原型 / 页面」时启用。

## 2. 技术选型

| 优先级 | 方案 | 何时用 |
| --- | --- | --- |
| 1 | **单文件 HTML**（内联 CSS/JS） | 绝大多数需求，双击即用 |
| 2 | 多文件静态站（`index.html` + `css/` + `js/`） | 逻辑超过 500 行 |
| 3 | Vite/React 工程骨架 | 用户明确要求框架，且接受后续要构建 |

禁止：需要后端才能跑的功能（除非用户提供 API 或明确接受 mock 数据）。

## 3. 目录结构

```
projects/<项目>/
├── README.md
├── PROJECT.md
├── AGENTS.md
├── plan/todo.md
├── src/
│   ├── index.html
│   ├── style.css
│   └── app.js
├── docs/
│   ├── architecture.md   # 页面 / 数据 / 接口
│   └── acceptance.md     # 验收清单
├── assets/
└── build/
```

## 4. 实现约定

- **响应式优先**：先按 375px 宽设计，`viewport` 必写，触控目标 ≥ 44px。
- **状态集中**：一个 `state` 对象 + 一个 `render()`，禁止散落 DOM 操作。
- **本地优先**：数据存 `localStorage`，键名 `pf.<项目>.data`；导出/导入 JSON。
- **无网可用**：不依赖外部 CDN；字体用系统栈。
- **可访问**：语义标签、`aria-label`、键盘可操作、对比度 ≥ 4.5:1。
- **错误可见**：失败时给用户中文提示，不静默吞异常。
- **安全**：不 `eval`，不 innerHTML 拼接用户输入（用 `textContent`），外部链接 `rel="noopener"`。

## 5. 交付节奏

| 阶段 | 产出 |
| --- | --- |
| P0 | `docs/architecture.md`（页面结构 + 数据流各一段） |
| P1 | 能打开、能操作的主界面（假数据） |
| P2 | 真实数据流 + 持久化 |
| P3 | 空状态 / 错误态 / 加载态 |
| P4 | README + `docs/acceptance.md` 逐条勾选 |

## 6. 设计约束

- 不用大面积紫/靛蓝渐变；不用 emoji 当图标。
- 圆角、间距、字号各不超过 3 档（如 8/12/20）。
- 深色模式用 `prefers-color-scheme` 适配，不做手动切换按钮（除非用户要求）。

## 7. 自检清单

- [ ] 手机浏览器可直接打开，无横向滚动
- [ ] 首屏不依赖网络
- [ ] 刷新后数据还在（localStorage）
- [ ] 空态/错误态都有文案
- [ ] 没有 `eval`、没有未转义的用户输入
- [ ] README 写明：功能 / 运行 / 已知限制
