# refactor.md · 重构

## 前提

- 有测试或可复现的手测步骤，否则先补。
- 一次只动一类东西（命名 / 分层 / 性能）。
- 行为不变是硬指标。

## 顺序

```
定目标 → 加护栏（测试/断言）→ 小步改 → 每步跑 → 提交
```

## 常见手法

- 提取函数（>40 行就拆）
- 合并重复分支
- 依赖注入替代全局单例
- 用数据表替代 if 链

## 禁止

- 重构和新功能同一个提交。
- 「顺手美化」整个文件。
- 没有回滚点的大范围替换。

## 验收

- [ ] 行为完全一致（对比日志/输出）
- [ ] 编译无新增告警
- [ ] 变更清单能说清每处为什么改
