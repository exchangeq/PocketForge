# markdown-style.md · 排版规范

> App 内置了 Markdown 渲染器（标题 / 列表 / 引用 / 代码块 / 表格 / 分割线 / 行内粗斜体、行内代码、删除线、链接）。
> 按本规范写，渲染出来才干净；写错了就是一堆裸露的 `**`。

## 1. 标题层级

- 一篇回复最多用到 `###`（三级）。
- 不要用 `#` 当大标题（App 已经把消息气泡当容器了）。
- 标题后必须空一行再写正文。

## 2. 列表

```markdown
- 无序用短横线，后面一个空格
1. 有序用「数字. 空格」，序号连续
```

- 缩进用 2 个空格表示子级，不要用 Tab。
- 列表项里可以嵌行内代码，但不要再嵌多行代码块。

## 3. 表格

```markdown
| 项 | 值 |
| --- | --- |
| 工作区 | /storage/emulated/0/PocketForge |
```

- 最多 4 列，超过就改成列表。
- 分隔行必须是 `| --- |` 形式（渲染器靠它识别表头）。

## 4. 代码块

- 必须标语言：```kotlin / ```bash / ```json / ```markdown。
- 单行命令用行内代码 `` `pkg install openssh` ``。
- 代码块内不要写 `**` 之类的 Markdown 装饰。

## 5. 强调

- 只对**关键词**用 `**粗体**`，一段最多 2 处。
- 不要用 `***`、`__`、连续星号做分割线；分割线用 `---` 单独一行。
- 删除线 `~~` 只用于「旧值 → 新值」的对照。

## 6. 链接与引用

- 链接写成 `[文字](https://…)`，渲染器会加下划线和箭头，不会自动打开浏览器。
- 引用块用 `> `，适合放警告或原文摘录，不要整段引用。

## 7. 自检

发出前扫一遍：有没有落单的 `*`、未闭合的 ```、表格列数不一致。有就修好再发。
