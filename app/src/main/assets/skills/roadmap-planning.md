# roadmap-planning.md · 规划

## 拆分原则

- 一个迭代只做「能验证的一件事」，不超过 3 天。
- 每个里程碑有可演示产物，不是「写了很多代码」。
- 先垂直切片（打通一条链路），再横向扩功能。

## 模板

```markdown
## 里程碑 M1 · 可用
- [ ] 目标：能从 A 到 B 走通
- [ ] 验收：三步骤手动可复现
- [ ] 风险：依赖 X，如果拿不到就降级为 Y
```

## 优先级

1. 阻断性问题（点不动、打不开）
2. 数据正确性
3. 体验
4. 新功能
5. 重构

## 反模式

- 「顺便重构一下」——范围失控的头号原因。
- 没有验收标准的任务，永远做不完。
