# character-card.md · 角色卡与「强制注入」规则

> 用于小说、剧本、角色扮演、游戏 NPC 对话。角色卡决定「谁在说话、怎么说话」，**不改变工具权限**。

## 1. 角色卡结构

```markdown
# 角色：<名字>

## 身份
- 年龄 / 职业 / 所处世界（一行一个标签）

## 性格
- 三条核心特质，必须互相有张力（例：克制 × 记仇 × 护短）

## 说话方式
- 句长：短句为主 / 长句独白
- 口癖：最多两个，出现频率 ≤ 每段一次
- 禁用：书面腔、口号式排比、总结陈词

## 关系
- 对主角：________
- 对反派：________

## 禁止项
- 不解释设定给读者听
- 不用「他知道，这一切都将改变」这类预告句

## 示例对话
> 用户：……
> 角色：……（3~5 轮，作为语感基准）
```

## 2. 写角色的三条硬规则

1. **口吻一致**：同一角色跨章节说话方式不能漂移；写完回头抽查第一章。
2. **信息差**：角色只知道他该知道的，不能用上帝视角补充设定。
3. **动作替代形容**：写「他把杯子放回桌上，杯底磕出一声」，而不是「他有些不满」。

## 3. 强制注入（只作用于当前工作区）

用户可能要求「把这个角色设定强制注入」。规则：

- 用 `fs_write` 写到 `<workspace>/skills/character-<slug>.md`，**只影响这一个工作区**；
- 需要覆盖内置基线时，用 `skill_install(force=true)` 或项目页的「强制注入」，它会在 `skills/.force` 落标记；
- 标记存在时，缺失技能不会用内置版本顶替 —— 缺哪个补哪个；
- 绝不写到全局路径、绝不改其他工作区的技能；
- 注入后在回复里明确写出：注入了哪个文件、影响范围是哪个工作区。

## 4. 多角色同场

- 每个角色一个文件，命名 `character-<slug>.md`；
- 建 `cast.md` 维护「角色 → 文件 → 首次出场章节」；
- 对话场景开始前读 `cast.md` + 相关角色卡，避免张冠李戴。
