# network-stability.md · 弱网与断线处理

> 手机端网络会在锁屏、切后台、地铁、电梯里反复断。出现失败先按这份流程排查，不要一上来就怪模型。

## 1. 分型判断

| 现象 | 大概率原因 | 正确处理 |
| --- | --- | --- |
| `HTTP 429` / `rate limit` / `TPM` | 上游限流 | 等 1–2 分钟；或调低 max_tokens / 换模型，别连续重发 |
| `HTTP 401/403` | Key 失效、欠费、模型没权限 | 让用户去设置核对 Key 与模型，不要重试 |
| `HTTP 404` | Base URL 或模型名不对 | 输出实际请求地址与模型名，让用户改 |
| 读超时 / `timeout` | 弱网、长回答被掐 | 先缩短单次目标；流式读超时 300s，不要重复点发送 |
| `Connection reset` / `unexpected end of stream` | 网络切换（WiFi↔流量） | 重发一次即可；仍失败提示换网络 |
| 空响应 | 上游偶发 | 客户端会自动重试 2 次，仍空就拆小目标 |

## 2. 客户端已做的加固（不用重复实现）

- 连接 15s、流式读 300s，单轮看门狗 300s；
- 连接阶段失败自动重试一次（已出字就不重试，避免重复内容）；
- 429 自动退避 6s/12s，并把 max_tokens 砍半；
- Termux SSH 连接池复用 90s，心跳 10s，失败重试 3 次；
- 下载器 4 段 Range 并行，失败自动回退单连接。

## 3. 给用户的回复模板

失败时不要只丢一句"失败了"：
1. 一句结论（哪一步失败、HTTP 码或网络类型）；
2. 一条最省事的修法（换网络 / 等 1 分钟 / 改模型名 / 缩短目标）；
3. 一条兜底（离线可先做本地文件操作，联网后再补）。

## 4. 禁止

- 禁止把超时说成"模型不会"；
- 禁止在没验证的情况下说"已经重新发送成功"；
- 禁止连续狂点重试（会把限流拖得更久）。
