# writing.md · 写作项目规范

## 1. 适用场景

长篇小说、短篇集、剧本、设定集、公众号长文、教材讲义、人物口述整理。
用户说「写本小说 / 规划大纲 / 整理设定 / 写一章」时启用。

## 2. 目录结构（强制）

```
projects/<项目>/
├── README.md            # 一句话简介 + 当前进度
├── PROJECT.md           # 项目卡
├── AGENTS.md            # 给 AI 的开工须知
├── plan/todo.md         # 章节进度表
├── outline.md           # 全书大纲（卷 → 章 → 一句话事件）
├── style-guide.md       # 文风约定 + 禁用词
├── characters/          # 每个主要角色一个 .md
│   └── <角色名>.md
├── worldbuilding/       # 世界观：地理/规则/势力/年表
├── chapters/
│   ├── 001-<标题>.md
│   └── 002-<标题>.md
├── notes/               # 灵感、伏笔、待核对清单
└── export/              # 合并稿、待发布版本
```

## 3. 开工顺序（不可跳）

1. **立意一句话**：谁，想要什么，被什么阻挡，代价是什么。
2. **`outline.md`**：先写卷，再写章，每章一句「事件 + 转折」。
3. **`characters/`**：主角 3 人以内先立住（欲望 / 恐惧 / 说话习惯）。
4. **`worldbuilding/`**：只写「会影响到情节」的设定，不做百科。
5. **`style-guide.md`**：定人称、时态、句长、禁用词。
6. **才开始写第一章**。

## 4. 章节写作规范

- 单章 2000–4000 字为一个交付单位；用户指定 15000 字/章时按用户要求拆成多段写入同一文件。
- 每章文件头写元信息：
  ```md
  ---
  chapter: 3
  title: 雨夜的交易
  pov: 林砚
  status: draft
  words: 3120
  ---
  ```
- 开头 200 字内必须出现「变化」（有人来了 / 东西丢了 / 决定做了）。
- 每章结尾留一个「未闭合的问题」，不要总结陈词。
- 对话占比 30%–50%；每段对话必须推进信息或关系。

## 5. 去 AI 味（硬规则）

避免：
- 排比三连（「不是…不是…而是…」）
- 空洞总结句（「这一刻，他明白了…」）
- 万能形容词（「深邃的眼眸」「空气中弥漫着」）
- 每段都以「他/她」开头的同构句
- 过度解释情绪（写出动作与生理反应，不写「他很愤怒」）

必须：
- 具体名词 > 抽象名词（写「搪瓷缸里的凉茶」，不写「饮品」）
- 长短句交错，允许不完整句
- 人物说话带口头禅/停顿/回避，不人人都是辩论冠军
- 同一场景内不重复使用同一个比喻

## 6. 一致性检查（每 5 章做一次）

- 时间线：日期、季节、人物年龄是否自洽
- 称呼：谁叫谁什么，是否随关系变化
- 能力/规则：世界观限制有没有被随意突破
- 伏笔表：`notes/伏笔.md` 记录「埋在第几章 / 计划第几章回收」

## 7. 导出

- `export/<项目名>-合并稿.md`：按章节顺序合并，保留分章标题。
- 需要 Word/EPUB 时：先产出 Markdown 合并稿，再在说明里给出转换方式（本机不直接生成 docx/epub 二进制）。

## 8. 自检清单

- [ ] 大纲每一章都有「事件 + 转折」
- [ ] 主角有明确的欲望与恐惧
- [ ] 本章开头 200 字内有变化
- [ ] 没有出现禁用词清单里的表达
- [ ] `plan/todo.md` 的进度与实际文件一致
