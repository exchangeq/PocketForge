# user-docs.md · 读取用户上传的文档

> 用户在项目页点「导入文档」后，文件会落到当前工作区 `docs/inbox/`。动笔前必须先读，不许凭印象写。

## 1. 读取顺序

```
① fs_list("docs/inbox")        # 看有哪些文件、大小
② fs_read("docs/inbox/<name>") # 逐份读，长文分段读
③ 记要点：在 plan 或 notes/ 里列「来源 → 结论」
```

## 2. 使用规则

- **引用要标源**：写"据 `docs/inbox/需求.docx.txt` 第 2 节"，不写"根据资料"。
- **冲突要说明**：两份文档口径不一致时，列出差异并让用户裁决，不擅自合并。
- **缺页要问**：文档被截断、乱码、只有目录时，直接说缺什么，别猜。
- **不外泄**：文档内容只用于当前项目，不写进其他项目目录，不发外部请求。
- **不改原件**：`docs/inbox/` 里的文件只读；要整理就另存到 `docs/notes/`。

## 3. 常见格式处理

| 格式 | 处理 |
| --- | --- |
| `.md` / `.txt` | 直接读，保留原有标题层级 |
| 纯文本导出的 PDF/Word | 按段落重排，去掉页眉页脚与断行 |
| 表格类文本 | 先还原成 Markdown 表格，再引用行列 |
| 代码/配置 | 原样引用，不改缩进 |

## 4. 交付时

- 在回复「文件」段写明读了哪些、用了哪几节。
- 用户文档里的专有名词、命名、口径，全项目沿用，不自行改名。
