# project-progress.md · 项目进度协议（每次开工必读）

> 目的：不管隔了几天、换了哪个模型，都能一眼看出「这个项目怎么做、上次做到哪一步」。

## 1. 进项目先读三样

1. `PROGRESS.md` —— 施工日志，最后一行就是上次停下的位置。
2. `PROJECT.md` —— 交付定义与验收标准。
3. `README.md` —— 怎么跑、目录说明。

三份都没读就动手 = 越界，工具层会拦。

## 2. 每次动手的固定节奏

```
① fs_read PROGRESS.md      # 看最后一行
② plan_set([...])          # 把接下来的 3–6 步写到 UI
③ 做一步 → 自检 → 再做下一步
```

- 每步工具执行后，系统会**自动**往 `PROGRESS.md` 追加一行（时间 · 动作 · 结果）。
- 不要重做日志里已完成的事；要改就写"返工：原因"。
- 一次只推进一个可验证的小步骤，别一口气写十个文件再一起编译。

## 3. 写入范围（硬约束）

- 在项目对话页里，只允许写 `projects/<当前项目>/` 下的文件。
- 想改别的项目：先切到那个项目的对话页，不要在 A 项目里改 B 项目。
- 公共区（`skills/`、`exports/`）由系统写，AI 不要直接动。

## 4. 交接写法（换人/换模型也能接）

在 `PROGRESS.md` 末尾留一段：

```
## 交接
- 已完成：<列表>
- 未完成：<列表 + 卡在哪>
- 下一步：<第一条具体动作>
- 注意：<坑 / 约束 / 别碰的文件>
```

## 5. 禁止

- 禁止把"计划"写成"已完成"。
- 禁止删掉历史日志行来假装没失败。
- 禁止在没有读 PROGRESS.md 的情况下重建整个项目。
